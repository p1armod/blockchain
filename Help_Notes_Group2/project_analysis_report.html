Big Picture

What Is This Project?

This is a Hyperledger Fabric-based Land Registration System built as an MCA Project-Based Learning assignment. The class is split into groups of 3 students. Each group is responsible for one organization in a shared blockchain network. All groups together operate a 3-organization Fabric network (Org1, Org2, Org3) plus an Orderer Org. Each folder represents one group's submission.

ℹ️
Note on Folder Names
Folders: 25CSMR07, 25CSMR09, 25CSMR11, 25CSMR23, 25CSMS12. All contain documentation and video. Folder 25CSMR09 contains the full extracted codebase (LandRecords.zip) with all actual source code — this is the primary working folder.
✅
What Has Been Built
Fully functional end-to-end system: Hyperledger Fabric network (3 orgs + orderer), Node.js chaincode (13 functions), Express.js REST API, Next.js 14 frontend, AES-256 encryption, IPFS document storage, AI-OCR pipeline (PyTesseract + SpaCy), Trust Scoring, DigiLocker integration. Tested on real P2P network via Tailscale VPN.

Application Lifecycle

How a Land Application Flows Through the System

A land application passes through a 12-stage multi-department workflow. Every step is an immutable blockchain transaction.

1
Citizen Registration & DID Creation
🏚 Org1 — Registration Department
Citizen registers via Next.js frontend. Fabric CA issues X.509 certificate. A Decentralized Identity (DID) is generated and stored on blockchain. Citizen authenticates via DigiLocker to retrieve government documents.
2
Land Application Submission
🏚 Org1 — Clerk → Superintendent → Project Officer
Citizen submits application. Sensitive data (Aadhaar, phone) is AES-256 encrypted via transient data map — never written to blockchain in plaintext. Documents uploaded to IPFS, CID stored on blockchain. Status: submitted → with_superintendent → with_project_officer.
3
Revenue Verification & Survey
💹 Org2 — MRO → Surveyor → Revenue Inspector → VRO
Revenue Dept receives application. MRO reviews, Surveyor submits land survey report, Revenue Inspector validates. AI-OCR extracts data from physical deed (Survey No., area, owner name). Trust Indexer calculates real-time integrity score. IPFS hash verified against on-chain CID. Status progresses through 4 Revenue stages.
4
Collectorate Final Approval
🔑 Org3 — Joint Collector → District Collector → Ministry of Welfare
Joint Collector reviews revenue-verified application. District Collector issues formal approval with digital certificate (blockchain TX ID). Ministry of Welfare gives final sign-off, setting status to completed. Permanent, immutable record on ledger.
5
Consent-Based Third-Party Access
🏦 External Party (Bank / Lawyer)
After registration, banks or lawyers can request read-only access. Citizen approves/rejects via consent module. Every access is permanently logged. Currently read-only — this is the gap the new Banking Feature addresses.
6
Blockchain Explorer & Audit Trail
📊 All Organizations
The Next.js Blockchain Explorer shows every transaction: who acted, when, what changed. The getHistory() chaincode function retrieves the immutable event log for any application ID.
Full Application Status Chain (12 Stages)
submitted→ with_superintendent→ with_project_officer→ with_mro→ with_surveyor→ with_revenue_inspector→ with_vro→ with_revenue_dept→ with_joint_collector→ with_collector→ with_ministry_welfare→ ✅ completed
Smart Contracts

All 13 Chaincode Functions Explained

All business logic lives in chaincode/land-registration/lib/land-registration-contract.js (584 lines). Deployed to mychannel with chaincode name land-registration.

initLedger()
All Orgs
Initializes chaincode on first deploy. Sets up ledger state.
createApplication()
Org1 — Registration Dept
Creates new land application. Encrypts sensitive data via AES-256 transient data map. Required role: applicant or admin.
verifyByRevenue()
Org2 — Revenue Dept
Revenue officer verifies application. Changes status from submitted to verified. Required role: officer or admin.
surveyReportUpdate()
Org2 — Revenue Dept
Surveyor submits land survey report. Restricted to Org2MSP by MSP ID check in chaincode.
forwardApplication()
All Orgs (role-based)
Advances application through 12-stage workflow. Enforces strict role transitions (Clerk→Superintendent→MRO→Surveyor→Collector). Key function to update for Banking Feature.
approveByCollector()
Org3 — Collectorate
District Collector approval. Ministry of Welfare completes registration (status: completed). Required role: collector or admin.
getApplication()
All Orgs (read)
Returns full application details. Decrypts AES data. Dynamically calculates M8 Trust Score (0-100) and injects M9 AI-OCR fields into response.
getAllLandRequest()
All Orgs (read)
Returns all applications via open-ended range query. Includes Trust Score and OCR data for each record.
getHistory()
All Orgs (read)
Returns immutable audit trail for an application — every action, who did it, when, what status changed.
recordDocumentIntegrity()
Org1 or Org2
Records SHA-256 hash + IPFS CID on blockchain for tamper-proof document anchoring. Used by M7 (security module).
queryByStatus()
All Orgs (read)
CouchDB rich query — returns all applications with a specific status (e.g. with_mro, completed).
_calculateTrustScore()
Internal — M8
Computes weighted Trust Score (0–100) based on history depth and verification stage. Not callable externally.
_generateAIOCRData()
Internal — M9
Generates AI-OCR extracted data (owner name, survey no., area, confidence) injected into API responses.

Enhancement Proposal

New Feature: Banking Org4 — Mortgage & Lien Management

The New_Idea/ folder has a detailed proposal for adding a 4th organization. 100% core blockchain development — Docker config, Node.js chaincode, REST API routes, Frontend dashboard.

🏦 Banking & Financial Organization (Org4)
Introduces a Financial Encumbrance (Lien) Management System to prevent fraud. When citizen takes a loan against their land, smart contract marks isMortgaged = true and the property is locked — any transfer attempt is automatically rejected until the loan is repaid and the lien is released.
Org4 · Peer 0 · Member 1
Loan Initiation & Consent Gateway
Entry point for financial transactions. Generates a Lien Request on the blockchain. Handles the cryptographic consent handshake between citizen and bank.
Org4 · Peer 1 · Member 2
Asset Verification & Due Diligence
Queries ledger World State: verifies citizen is the true owner, validates Trust Index, and ensures no other bank holds an active lien (prevents double-mortgaging).
Org4 · Peer 2 · Member 3
Lien Endorsement & Enforcement
Final transaction endorser. Invokes chaincode to set isMortgaged = true and record bank's ID. When loan repaid, executes releaseLien() to unlock the property.
🛠 Exact Code Changes Needed (6 Tasks)
placeLien(propertyId, bankId, loanAmount)
New function — Org4
Sets isMortgaged = true, records lienHolder and loan amount. Checks no existing lien active. Requires Org4MSP endorsement.
releaseLien(propertyId, bankId)
New function — Org4
Sets isMortgaged = false, clears lienHolder. Only callable by the bank that placed the lien. Logs release in history.
getLienStatus(propertyId)
New read function — Org4
Returns: isMortgaged, lienHolder, loan amount, and lien timestamp.
forwardApplication() — Guard Update
Modify existing function
Add: if application.isMortgaged === true, throw error rejecting any transfer or status change. Protects bank's collateral.
Asset Schema — New Fields
Modify createApplication()
Add to application object: isMortgaged: false, lienHolder: null, lienAmount: 0, lienTimestamp: null.
Org4 Network Config
Docker / Fabric Infrastructure
Add Org4 to crypto-config.yaml, configtx.yaml, docker-compose.yaml. Create setorg4.sh and fabric-api/src/org4/ connection profile.
